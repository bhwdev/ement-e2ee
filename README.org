#+title: ement-e2ee
#+options: ^:{}

A transparent end-to-end-encryption proxy that gives the Emacs Matrix client
[[https://github.com/alphapapa/ement.el][ement.el]] full E2EE support — without modifying ement at all. It uses the
official [[https://github.com/matrix-org/matrix-rust-sdk][matrix-sdk-crypto]] (vodozemac; the same crypto core Element uses)
instead of the deprecated libolm (which pantalaimon was based on).

The Emacs package =ement-e2ee.el=, in this repository, installs the proxy,
runs it while ement needs it and routes ement through it: after
~M-x ement-e2ee-install~, ~M-x ement-connect~ works as before, with
encryption.

#+begin_example
Emacs / ement.el  ──plain HTTP──▶  ement-e2ee (localhost)  ──HTTPS──▶  homeserver
                                   · decrypts m.room.encrypted in sync/history
                                   · encrypts your sends (megolm)
                                   · device keys, to-device, key requests
                                   · SSSS recovery, cross-signing, key backup
                                   · encrypted attachments
#+end_example

* Features

- *Receive*: decrypts ~m.room.encrypted~ events in ~/sync~, ~/messages~,
  ~/context~, ~/event~, and ~/notifications~ responses; undecryptable events
  render as a readable placeholder and trigger an automatic room-key request.
  When the key arrives later, the placeholder is replaced in place.
- *Send*: transparently encrypts everything sent into encrypted rooms
  (messages, edits, reactions), including establishing olm sessions and
  sharing megolm keys with full (not lazy-loaded) room membership.
- *Join your existing identity*: ~M-x ement-e2ee-bootstrap~ (or
  ~ctl bootstrap~) takes your recovery key or passphrase, imports your
  cross-signing keys from SSSS, signs this device (green shield in Element),
  and restores your history keys from server-side key backup. New room keys
  are backed up automatically afterwards.
- *Verification*: emoji (SAS) verification against your other devices via
  ~M-x ement-e2ee-verify~ (~ctl verify~), which asks one question: do the
  emoji match?
- *Diagnostics*: ~M-x ement-e2ee-check~ (~ctl debug check~) tests the
  whole chain and names the remedy for each problem; further subcommands look
  into a room, an event, the device lists or the logs.
- *Media*: uploads are encrypted (spec ~EncryptedFile~, AES-CTR), downloads
  decrypted on the fly — including ement's tokenless avatar fetches. Media
  sent to unencrypted rooms is re-uploaded as plaintext automatically.
- *Multi-account*: sessions are keyed by access token; each gets its own
  sqlite crypto store under =~/.local/share/ement-e2ee/=.

* Install

** The Emacs package

Install it from Git, with whichever package manager you use (it needs Emacs
28.1 or newer, ement 0.16 or newer, and plz):

#+begin_src emacs-lisp
;; package-vc (Emacs 29+)
(package-vc-install "https://github.com/bhwdev/ement-e2ee")
;; or, Emacs 30+:
(use-package ement-e2ee
  :vc (:url "https://github.com/bhwdev/ement-e2ee"))

;; straight.el
(straight-use-package '(ement-e2ee :host github :repo "bhwdev/ement-e2ee"))

;; elpaca
(elpaca (ement-e2ee :host github :repo "bhwdev/ement-e2ee"))
#+end_src

Then, once:

#+begin_example
M-x ement-e2ee-install
#+end_example

It

1. gets the proxy binary, after asking how: *download* the release's
   prebuilt binary (static Linux x86_64 and aarch64, Apple Silicon macOS),
   checked against the release's =SHA256SUMS= before it is used; or *build*
   it with ~cargo install --locked~ (Rust ≥ 1.96), from the package's own
   checkout when its version matches. It goes to =ement-e2ee/VERSION/bin/=
   under ~user-emacs-directory~ (~ement-e2ee-binary-directory~). A new
   enough ~ement-e2ee~ on ~exec-path~, or ~ement-e2ee-program~, is used
   instead;
2. asks for your Matrix user ID and writes the proxy's config, unless there
   is one (~ement-e2ee setup~, below);
3. turns on ~ement-e2ee-mode~, and offers to keep it on in future sessions
   (with Customize). With use-package, ~:config (ement-e2ee-mode)~ does the
   same.

Then ~M-x ement-connect~, as usual. Once connected, join your encrypted
identity with ~M-x ement-e2ee-bootstrap~ (it asks for the recovery key) and,
optionally, verify the device with ~M-x ement-e2ee-verify~; after the first
sync, a device that is not cross-signed yet gets a hint to do so.

The prebuilt binaries carry a build-provenance attestation, which ties them
to the release workflow run that built them:

#+begin_src sh
gh attestation verify ement-e2ee-x86_64-unknown-linux-musl -R bhwdev/ement-e2ee
#+end_src

Elsewhere (Intel macOS, other Unix systems) ~ement-e2ee-install~ offers the
cargo build only. Native Windows is not supported; WSL is.

** What the mode does

- ~ement-connect~ starts the proxy when an account it routes needs it
  (~ement-e2ee-accounts~: all, or a list of user IDs), points the session at
  it (also a session ement saved earlier) and waits until it answers. A
  missing binary or config is dealt with first, as ~ement-e2ee-auto-install~
  says (ask, by default).
- The proxy runs as a subprocess of Emacs, its output in the =*ement-e2ee*=
  buffer (~M-x ement-e2ee-log~). When it dies, Emacs restarts it, backing off
  (1 s, 2 s, 4 s, … at most 60 s), and resumes ement's syncs, which ement
  itself gives up after a failed connection. After four failed starts in a
  row it stops trying and shows a warning with the proxy's last words.
- When the last session using it disconnects, the proxy is stopped
  (~ement-e2ee-stop-on-disconnect~). When Emacs exits, however it exits, the
  proxy follows: on SIGHUP, or when its standard input, a pipe from Emacs,
  reaches end of file.
- A proxy already running on the configured port (from another Emacs, or
  started by hand) is used rather than a second one started, and replaced
  when it disappears. Only a proxy this Emacs started is stopped
  automatically.
- Turning the mode off leaves a running proxy alone; ement's saved sessions
  keep pointing at it.
- After an update of the package, the first ~ement-connect~ gets the binary
  the new version needs, as ~ement-e2ee-auto-install~ says (by default it
  asks, naming the version installed), and restarts a proxy this Emacs runs
  with it, or replaces an older one found running, after asking. Once the
  new proxy answers, the older binaries under ~ement-e2ee-binary-directory~
  are deleted: it has marked the store as its own, so they would refuse to
  start there anyway. The config, and the store with its device, are kept.

Commands:

| Command                                 | What it does                                                                |
|-----------------------------------------+-----------------------------------------------------------------------------|
| ~ement-e2ee-install~                    | get the binary and config, turn the mode on (~C-u~: fetch the binary again) |
| ~ement-e2ee-setup~                      | write the config afresh, for another account or homeserver                  |
| ~ement-e2ee-bootstrap~                  | join your encrypted identity with the recovery key                          |
| ~ement-e2ee-verify~                     | emoji-verify against another device, in a comint buffer                     |
| ~ement-e2ee-check~                      | ~ctl debug check~: what is wrong, and the remedy                            |
| ~ement-e2ee-status~                     | ~ctl status~: sessions, cross-signing, key backup                           |
| ~ement-e2ee-log~                        | the proxy's log                                                             |
| ~ement-e2ee-start~, ~-stop~, ~-restart~ | by hand                                                                     |
| ~ement-e2ee-delete-old-binaries~        | remove binaries of older versions                                           |

Settings are in ~M-x customize-group RET ement-e2ee~; among them
~ement-e2ee-config-file~ (another config file), ~ement-e2ee-serve-arguments~
(e.g. ~("--log-level" "debug")~) and ~ement-e2ee-startup-timeout~. One proxy
serves one homeserver: route only accounts on the homeserver in its config.

** Without Emacs's help

Build and install the binary by hand (Rust ≥ 1.96, ~rustup~ recommended). All
dependencies, including the
[[https://github.com/matrix-org/matrix-rust-sdk][matrix-rust-sdk]] crates, are
released versions from crates.io, locked by =Cargo.lock=.

Rust older than 1.96 (Guix has 1.93) cannot build 0.19 (upstream dependency):
checkout =v0.18.0= or use a static prebuilt binary. That refuses a store 0.19
has used.

#+begin_src sh
cargo install --locked --path .   # puts ement-e2ee on ~/.cargo/bin
#+end_src

Then

#+begin_src sh
ement-e2ee setup --user-id @you:example.org
#+end_src

finds your homeserver (via =.well-known=), writes
=~/.config/ement-e2ee/config.toml=, and prints how to start the proxy and the
~ement-connect~ form to evaluate in Emacs. ~--homeserver URL~ skips
discovery, and an existing config is kept unless ~--force~ is given. Then run
the proxy, connect ement through it and, with ement connected:

#+begin_src sh
ement-e2ee serve             # in a terminal of its own
ement-e2ee ctl bootstrap     # join your encrypted identity (asks for the recovery key)
ement-e2ee ctl verify        # optional: emoji-verify against another device
ement-e2ee ctl debug check   # is everything in order?
#+end_src

~ctl bootstrap~ imports your cross-signing keys from secret storage, signs
this device and restores your key backup; the recovery key is prompted for
(or read from ~--recovery-key-file~), never passed via argv.

~ctl verify~ waits for a verification started on your other device (in
Element: Settings → Sessions → the ement session → Verify), or starts one
itself with ~--device DEVICEID~. It shows the emoji, asks whether the other
device shows the same, and reports the result. Keep ement connected while it
runs.

To write the config by hand instead of with ~setup~:

#+begin_src sh
mkdir -p ~/.config/ement-e2ee
cp config.example.toml ~/.config/ement-e2ee/config.toml
$EDITOR ~/.config/ement-e2ee/config.toml   # set homeserver
#+end_src

and connect with

#+begin_src emacs-lisp
(ement-connect :user-id "@you:example.org"
               :uri-prefix "http://localhost:8009")
#+end_src

On first sync the proxy registers device keys for ement's device; it shows
up in Element → Settings → Sessions.

* Configuration

=config.example.toml= lists every setting. Beyond ~listen~ and ~homeserver~:

- ~store_passphrase_command~ — a shell command that prints the passphrase
  encrypting the crypto store (~pass show …~, ~secret-tool lookup …~), so it
  need not sit in the file. ~store_passphrase~ holds it directly instead.
- ~admin_token~ — the token the ~/_ement~ admin API requires. Without it,
  the proxy draws a new one each time it starts and writes it to
  =.admin-token= in the store directory. ~ctl~ finds it either way, and the
  listen address, through the same config file (~ctl --config FILE~ for a
  non-default one). By hand: ~curl -H "Authorization: Bearer $(cat
  ~/.local/share/ement-e2ee/.admin-token)" http://127.0.0.1:8009/_ement/status~.
- ~store_dir~ — a leading =~= is expanded.

~homeserver~ has to be https; plain http is accepted only for a homeserver on
this machine (127.0.0.1, ::1, localhost), and redirects from https to http
are not followed.

~ement-e2ee info [--json]~ shows what a proxy started with the config would
use: the listen address and URL, the homeserver, the store directory.

The proxy shuts down cleanly on SIGINT, SIGTERM and SIGHUP, and, with
~serve --exit-on-stdin-close~ (as Emacs runs it), when its standard input
reaches end of file; requests in flight get three seconds to finish.

* Admin CLI

#+begin_example
ement-e2ee info [--json]
ement-e2ee ctl status
ement-e2ee ctl bootstrap [--recovery-key-file FILE]
ement-e2ee ctl verify [--device DEVICEID] [--timeout SECS]
ement-e2ee ctl verify list|start|show|accept|start-sas|sas-accept|confirm|mismatch|cancel
ement-e2ee ctl keys export FILE   # passphrase-protected, Element-compatible
ement-e2ee ctl keys import FILE
ement-e2ee ctl debug check|session|devices|room|event|logs|log-level|report
#+end_example

The CLI talks to ~/_ement/*~ on the proxy's listen address, which it takes
from the config file (~--proxy URL~ overrides it). The ~verify~ subcommands
perform single steps of a flow, for scripting. ~GET /_ement/version~ (name,
version and process ID) is the one route open without the admin token: it is
how Emacs tells the proxy from anything else on the port. Asked with
~?nonce=HEX~, it adds a ~proof~: the HMAC-SHA256, keyed with the admin token,
of =ement-e2ee version ADDRESS NONCE=. Emacs uses a proxy only if it can
check that proof against the token file of its config's store directory,
which only its owner can read. A process of another user, or a Windows one
under WSL2, that takes the port first cannot pass it, and so never gets
ement's password and access tokens.

* Debugging

Start with ~M-x ement-e2ee-check~ (~ement-e2ee ctl debug check~). It tests the homeserver connection,
the clock, the access token, the published device keys and one-time keys,
cross-signing, the key backup, whether ement is syncing and the messages
still waiting for keys, and prints what to do about each problem; it exits non-zero
if a check fails. Then, as needed:

#+begin_example
ement-e2ee ctl debug event ROOM_ID EVENT_ID   # why this message does (not) decrypt, and the fix
ement-e2ee ctl debug room ROOM_ID             # encryption settings, recipients' devices, placeholders
ement-e2ee ctl debug devices [USER_ID]        # devices and how far each is trusted
ement-e2ee ctl debug session                  # sync activity, counters, pending work
ement-e2ee ctl debug logs [--level warn]      # recent log lines, kept in memory
ement-e2ee ctl debug log-level ement_e2ee=debug   # change the log filter without a restart
ement-e2ee ctl debug report --output FILE     # all of it as JSON, for a bug report
#+end_example

Every subcommand takes ~--json~ for the proxy's raw answer and ~--user-id~
to pick a session when several accounts are connected. The report contains
Matrix IDs and public keys, but no tokens, passphrases or private keys.

* Caveats

- *Late keys repair placeholders in place, as edits.* When the key for an
  "undecryptable" placeholder arrives (from the sender, another device, a key
  import or ~ctl bootstrap~), the proxy hands ement an edit that replaces the
  placeholder, so the message carries ement's ~[edited]~ marker. Reactions
  and other non-message events become a one-line note instead; reopening the
  room renders them properly. Placeholders in the notifications buffer are
  not repaired, and the proxy forgets which placeholders it has handed out
  when it restarts.
- *The proxy only pumps crypto while ement is syncing* (its long-poll is the
  heartbeat): room keys and verification messages reach the proxy inside
  ement's ~/sync~ responses. Keep ement connected during ~ctl verify~;
  ~ctl debug check~ warns when it has not synced for two minutes.
- *Session restore*: if you use ~ement-save-sessions~, the proxy re-learns
  the session from the token via ~/account/whoami~ — nothing to do. If you
  log out (token invalidated), the session is evicted; log in through the
  proxy again. A saved session whose store is gone is refused: see
  [[#devices][Devices]].
- *Tokenless media* (room avatars): ement fetches these without auth; the
  proxy borrows an active session's token upstream. With zero sessions they
  pass through untouched.
- *Trust model*: the proxy decrypts regardless of sender-device trust
  (ement has no UI to distinguish) and shares room keys with all devices in
  the room, like other clients' defaults.
- *WSL2*: keep the clock NTP-synced (crypto is timestamp-sensitive), bind
  only on 127.0.0.1 (default), and note that localhost is shared with Windows
  processes: one reason the admin API always needs its token.
- *Browsers*: the proxy answers only requests addressed to an IP address or
  to localhost, so a web page cannot reach it under a name of its own (DNS
  rebinding). The admin API turns away any request that carries an =Origin=,
  and every response tells browsers not to run scripts in it or embed it
  elsewhere (=Content-Security-Policy: sandbox=, =nosniff=,
  =Cross-Origin-Resource-Policy=). A decrypted attachment is offered as a
  download unless its type is one a browser shows harmlessly.
- *Forged events*: a decrypted event keeps only its type and content; the
  relation (edit, reply, reaction) is the one in the clear, as the homeserver
  and Element see it. Encrypted events of types only the homeserver sends
  (state, redactions, receipts, typing) are shown as a notice saying so:
  otherwise any member of a room could rename it for ement, change who is
  in it and what they are called, or hide others' messages.

* Devices
:PROPERTIES:
:CUSTOM_ID: devices
:END:

A device keeps its identity keys for life. Other clients never accept new
keys for a device ID they know, and Synapse keeps the cross-signing signature
made over the old ones and ignores every later one. ement, though, asks for
the same device ID on every login, whatever has become of the store. So the
proxy decides which device a login is:

- *There is a store for it*: the login continues that device, however often
  ement logs in. If the session was signed out from another client in the
  meantime, the proxy publishes the device's keys again; it is the same
  device as before.
- *There is none* (the first login, or the store directory was deleted):
  the login is a new device, under an ID the homeserver assigns. Verify it
  (~ctl bootstrap~), and sign the old session out from another client.

A session that arrives without a login — one ement saved and restored — is
refused when its device has keys on the homeserver that the proxy does not
hold: the store directory was deleted, or another program has used the
session. Those keys cannot be replaced. ement's sync then fails, and
~ctl debug check~ says why; ~C-u M-x ement-connect~ logs in again, as a new
device.

To start over: sign the ement session out from another client, delete its
store directory, connect again.

* Storage

=~/.local/share/ement-e2ee/{user}/{device}/=:

- =matrix-sdk-crypto.sqlite3= — olm account, sessions, room keys, trust state
  (optionally encrypted with ~store_passphrase~).
- =media.sqlite= — mxc → attachment encryption keys (needed to decrypt media
  you've received/sent; deleting it makes old encrypted media undownloadable
  until re-fetched keys arrive by other means).
- =login.json= — the device ID ement asks for at login, where the proxy chose
  another: how the next login finds this device again.

The store directory, which the proxy keeps accessible to its owner only
(mode 700, and everything it creates in it 600), holds =.admin-token=, the
admin token of the proxy using it; =.lock=, which keeps a second proxy (on
another port, say) from using the same stores while one runs; and
=.version=, the newest ement-e2ee that has used it: an older one refuses to
start there, since it cannot read what a newer one may have migrated. It
says which version to install; delete =.version= only if you are certain.
Each crypto store's own schema version is checked as well (stores from
before =.version= existed have only that): a store migrated by a newer
matrix-sdk-sqlite than the proxy's is refused.

Deleting a store directory starts a new device with the next login (see
[[#devices][Devices]]); it does not repair the old one. The room keys in it are
gone too, except for those the key backup brings back with ~ctl bootstrap~.
Prefer keeping it; back it up if you care.

* Development

#+begin_src sh
cargo test          # unit tests plus end-to-end tests (see below)
cargo +1.96 test --locked   # oldest Rust that Install promises
cargo run -- serve --homeserver https://matrix.org --log-level debug
curl http://127.0.0.1:8009/_matrix/client/versions   # smoke test
#+end_src

The end-to-end tests (=src/e2e_tests.rs=) run real matrix-sdk-crypto machines
through the proxy against an in-process fake homeserver (=src/testutil.rs=),
over loopback HTTP: message round trips, ~/notifications~ and history
decryption, media, key export/import, placeholder repair, device IDs across
logins, sign-outs and deleted stores, ~ctl bootstrap~ (SSSS, cross-signing,
backup restore), ~ctl verify~ (SAS, interactive and step by step) and
~ctl debug~. =tests/process.rs= runs the built binary:
signals and end of file on standard input, exit codes, the store lock and
version marker, ~ctl~ against a live proxy, ~info~, ~setup~. None of it needs
a network or an account.

The Emacs package's tests (=test/ement-e2ee-test.el=, ERT) run in batch
mode with ement, plz and ement's other dependencies on the ~load-path~; the
ones that start a real proxy need ~EMENT_E2EE_TEST_PROGRAM~:

#+begin_src sh
cargo build
EMENT_E2EE_TEST_PROGRAM=target/debug/ement-e2ee \
  emacs -Q --batch -L . -L PATH/TO/ement -L PATH/TO/plz ... \
  -l test/ement-e2ee-test.el -f ert-run-tests-batch-and-exit
#+end_src

CI (=.github/workflows/ci.yml=) runs ~cargo fmt~, clippy and the tests on
stable and on Rust 1.96; then it byte-compiles the package with warnings as
errors and runs the ERT tests on Emacs 28.2, 29.4 and 30.2, and checkdoc and
package-lint on 30.2.

* Releasing

The version follows
[[https://github.com/matrix-org/matrix-rust-sdk/releases][matrix-rust-sdk]]'s:
ement-e2ee 0.19.x is built on matrix-sdk-crypto 0.19.

1. In one commit, set the same version in =Cargo.toml= (~version~, then
   ~cargo build~ to update =Cargo.lock=), in =ement-e2ee.el='s
   ~;; Version:~ header and in its ~ement-e2ee-binary-version~.
2. Tag that commit ~vX.Y.Z~ and push the tag alone
   (~git push origin vX.Y.Z~). The release workflow
   (=.github/workflows/release.yml=) checks that the three versions and the
   tag agree, runs the tests, builds the binaries, writes =SHA256SUMS=,
   attests the binaries' provenance and publishes the GitHub release. Run
   the workflow by hand with ~dry_run~ to build the binaries as workflow
   artifacts, without a release.
3. Once the release is published, push main. Do not rewrite the tagged
   commit afterwards: the tag has to stay on main.

Whoever installs the package from Git (package-vc, straight, elpaca, MELPA
unstable) follows the main branch, so the elisp there must always work with
the binary its ~ement-e2ee-binary-version~ names, and that binary must be
downloadable: raise the version only in a release commit, and let main reach
that commit only after its release is out (step 3). Pushed earlier, main
sends everyone who updates meanwhile to a release that is not there (they
are told to try again later). The config must stay readable by newer
versions too, since an update keeps it and unknown keys are an error
(~deny_unknown_fields~): give a renamed key a serde alias for its old name,
and keep accepting a dropped one. MELPA takes the recipe
~(ement-e2ee :fetcher github :repo "bhwdev/ement-e2ee" :files ("ement-e2ee.el"))~.
